# =========================
# Cloudflare Turnstile - bot protection on the public auth forms
# =========================
# Guards sign-in, sign-up, forgot-password and invite acceptance with a
# Cloudflare challenge. Turnstile is the one Cloudflare product this deployment
# can use: it is a browser widget plus a server-to-server verification call, so
# it needs no custom domain and nothing proxied through Cloudflare's edge.
#
# OFF unless this is exactly "1", "true", "yes" or "on" AND both keys below are
# filled in. Leave it empty until an operator deliberately turns it on. These
# four endpoints are the only doors into the product, so if challenges start
# failing, set this back to empty: the value is re-read on every request, so a
# secret change is enough and no deploy, rebuild or code change is needed.
#
# A half-configured deployment stays OFF rather than turning on and locking
# everyone out: the flag alone does nothing, the secret alone does nothing, and
# a secret without a site key would refuse every human on the login page
# because the browser would have no way to mint a token.
TURNSTILE_ENABLED=""

# Public widget key from the Cloudflare dashboard (Turnstile > Add widget).
# Served to browsers by GET /api/auth/turnstile-config and rendered into the
# page, exactly like GOOGLE_CLIENT_ID. Not a secret - but the widget cannot be
# drawn without it, which is why an empty value counts as "off".
TURNSTILE_SITE_KEY=""

# Server-side key for challenges.cloudflare.com/turnstile/v0/siteverify. A real
# secret: never returned by any endpoint, never logged, never in a page.
#
# While enabled the guard fails CLOSED, and that includes a Cloudflare outage:
# a missing, blank, replayed or rejected token is refused with 403, and a
# siteverify call that times out or cannot be parsed is refused with 503. A
# challenge that waves requests through whenever one HTTP call struggles is
# decoration, so the escape hatch during an outage is TURNSTILE_ENABLED above,
# not a silent fallback.
